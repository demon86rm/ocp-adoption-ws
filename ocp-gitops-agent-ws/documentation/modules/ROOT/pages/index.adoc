== RHACM-style delivery for a handful of clusters, without the ACM subscription

Run application delivery for 3 to 6 clusters from one hub. A small team labels each cluster, writes one Helm chart or Kustomize base, and the Argo CD Agent delivers it to every matching cluster over an outbound connection. This workshop builds that setup step by step on one hub and two spokes.

IMPORTANT: Draft. Commands have not been run on a cluster yet and no timings are measured. Each step page says what is validated.

== How it fits together

[source,text]
----
            hub cluster                                spoke cluster (x2)
  +-------------------------------+            +----------------------------+
  | Argo CD (UI, API, repo-server)|            | Argo CD (app controller,   |
  | Principal  <------------------+-- mTLS ----+ repo-server, redis)        |
  | resource proxy                |  gRPC :443 | Agent                      |
  | one namespace per agent       |            | workloads                  |
  +-------------------------------+            +----------------------------+
----

The spokes open the connection to the hub. The hub never holds credentials for a spoke API server.

[cols="2,3",options="header"]
|===
| Part | Job
| Principal (hub) | Accepts agent connections, mirrors applications, proxies live-resource requests
| Agent (each spoke) | Connects out to the Principal, applies and reports applications
| `argocd-agentctl` (workstation) | Creates the lab CA and certificates, JWT key, and registers each agent
|===

For "govern everything from one hub", use *managed* mode: the hub is the source of truth and every `Application` is created on the hub.
