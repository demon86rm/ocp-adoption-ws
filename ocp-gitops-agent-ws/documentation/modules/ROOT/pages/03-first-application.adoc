= Step 3 - First Application: Deploy from the Hub to a Spoke
include::_attributes.adoc[]

This step creates one `Application` on the hub and watches it reach `spoke-a`. It proves the whole chain before the fleet step adds tags, Helm and Kustomize.

== Prerequisites

* xref:02-register-spokes.adoc[Step 2] finished: both agents show as connected.
* The sample application lives in the public repository `https://github.com/demon86rm/ocp-gitops-fleet-sample`. Argo CD needs no credentials to read it. Fork it when you want to change it.

== How It Works

The `Application` lives in the hub's `openshift-gitops` namespace. `destination.name` is the agent name, and the Principal sends the application to that agent. The spoke's own controller renders and applies it, and `selfHeal` reverts changes made by hand.

The label `argocd.argoproj.io/managed-by` on the target namespace says which Argo CD instance on the *spoke* may manage it. On a normal spoke that is `openshift-gitops`. `spoke-a` runs its own instance called `gitops-spoke-a`, so the manifest uses that name. With the wrong value the sync fails with `forbidden`.

== Steps to Apply

[#deploy]
=== 1. Create the Application on the hub

icon:clock[] ~30 seconds from apply to `Synced` and `Healthy` (measured once on ROSA HCP)

*What:* Apply `03-first-application/application-first.yaml` on the hub.

*Why:* The `Application` object is the only thing you create. The workload appears on the spoke.

[.console-input]
[source,bash]
----
oc apply -f 03-first-application/application-first.yaml --context hub
----

.Verify: the application is Synced and Healthy and the workload runs on the spoke
[%collapsible]
====
[.console-input]
[source,bash]
----
oc get application.argoproj.io hello-first -n openshift-gitops --context hub
oc get deploy,route -n first-app --context spoke-a
----

[.console-output]
[source,bash]
----
NAME          SYNC STATUS   HEALTH STATUS
hello-first   Synced        Healthy

NAME                    READY   UP-TO-DATE   AVAILABLE
deployment.apps/hello   1/1     1            1

NAME                             HOST/PORT
route.route.openshift.io/hello   hello-first-app.apps.<cluster domain>
----

Open the route in a browser. The page says `environment: test`. The hub UI shows the application and its live resources through the resource proxy.
====

'''

=== 2. Check that self-heal reverts a manual change

icon:clock[] ~30 seconds

*What:* Delete the deployment on the spoke and watch it come back.

*Why:* This is the difference between managed mode and "someone installed it once". The hub copy is the source of truth.

[.console-input]
[source,bash]
----
oc delete deployment hello -n first-app --context spoke-a
oc get deployment -n first-app --context spoke-a --watch
----

.Verify: the deployment is recreated
[%collapsible]
====
[.console-output]
[source,bash]
----
NAME    READY   UP-TO-DATE   AVAILABLE
hello   1/1     1            1
----
====

'''

|===
| Approach | Notes

== Reset

Delete the application on the hub. `prune: true` removes the workload with it.

[.console-input]
[source,bash]
----
oc delete application.argoproj.io hello-first -n openshift-gitops --context hub --ignore-not-found --wait
oc delete namespace first-app --context spoke-a --ignore-not-found
----

The order matters: deleting the application first lets Argo CD prune the workload cleanly. The namespace delete only catches leftovers.
